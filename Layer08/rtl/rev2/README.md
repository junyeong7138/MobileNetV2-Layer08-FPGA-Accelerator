# rev2 — PW1 풀 오버랩 (피드백 ④ 대응) 🚧

rev1 대비 **기능 불변·클럭만 감소**가 목표인 성능 개선판.
발표 피드백("노는 PE를 없애라, 무엇을 흘리고 무엇을 흘리지 말지 생각하라")의 구현이다.

**현재 상태 (2026-08-05): rev1과 파일 단위로 완전 동일한 복사본 — 오버랩 작업 미착수.**

## 목표 수치

| 항목 | rev1 (before) | rev2 목표 (after) |
|---|---|---|
| 총 클럭 | 87,169 | **~75,300** (이론 하한 75,264 + 최초 LOAD/마지막 DRAIN) |
| 곱셈기 활용률 | 86.3% | **99.9%** |
| 타일 간 idle | 31클럭 (LOAD 8 + DRAIN 23) | **0** — bank0 valid 윈도우가 196클럭 간격으로 텀 없이 연속되면 성공 |

## 설계 계획 (노션 3-2 §5.3)

1. **PE에 w_shadow 추가** — `load_mode`는 CALC 중에도 켜져 **섀도 체인만** shift-in
   (w_active 불변, 곱셈은 계속 w_active). 비용 = FF 1,024 + 16b mux 64.
2. **태그 스왑** — 전역 스왑 펄스는 skew 때문에 오답 (PE(i,j)의 경계 도착이 i+j클럭씩 다름).
   x 스트림에 1비트 경계 태그를 실어 skew_regs·x_out 체인을 데이터와 함께 타게 하고,
   태그를 본 PE만 그 클럭에 w_active ← w_shadow. **타일 마지막 x에 태그** (다음 클럭 첫 새 x부터 새 가중치).
3. **Ctrl_FSM 재편** — 정상 상태에서 LOAD·DRAIN 상태 소멸:
   `IDLE → PRELOAD(최초 8) → STREAM(384타일 × 196 연속, 경계마다 태그 발행 + 섀도 로드 스케줄) → DRAIN(마지막 타일만 23) → DONE`.
   valid 윈도우는 연속 카운터에서 타일 인덱스·오프셋으로 유도.
4. 누산 버퍼는 de-skew 주소 방식 그대로, 쓰기 주소에 타일 인덱스만 반영.

## 검증 기준 (중요)

- **출력은 rev1과 비트 단위로 동일해야 한다** — 골든·전수 채점 하네스(`../../sim/tb_Layer08.v`)를 그대로 리그레션으로 사용. 달라지는 것은 pw_done 클럭 수뿐.
- before/after 파형 비교: rev1의 "bank0 valid 사이 31클럭 텀"(2026-08-04 파형 분석)이 사라졌는지가 판정 기준.
