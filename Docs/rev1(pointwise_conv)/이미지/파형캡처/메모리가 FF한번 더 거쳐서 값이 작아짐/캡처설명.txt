 Layer08 Pointwise Conv — 파형 캡처 10장 상세 설명
 (Vivado xsim 행위 시뮬레이션, 디버그 데이터셋 사용)
================================================================================

■ 시뮬레이션 조건
  - 데이터셋: 디버그판 (Data/Debug/)
      입력   = 모든 채널 동일, 위치 p%4에 따라 1.0 / 1.5 / 2.0 / 2.5 (Q3.12)
      가중치 = 짝수 필터 +0.03125, 홀수 필터 -0.03125 (2^-16)
      기대 출력(64ch 완성) = ±2.0 / ±3.0 / ±4.0 / ±5.0
      기대 부분합(8ch, 타일 1개분) = ±0.25 / ±0.375 / ±0.5 / ±0.625
  - 파형 radix: 입력 Fixed 12, 가중치 Fixed 16, 뱅크(acc) Fixed 28
      ※ 뱅크 소수부는 26이 아니라 28이 맞음 (12+16=28).
        캡처의 숫자들은 28 기준으로 해석해야 딱 떨어지며, 실제 캡처값들도
        28 기준과 일치한다 (아래 참조).
  - 타이밍 상수: OFFSET = PE_ROW(8) + MUL_LAT(4) + MEM_LAT(1) = 13

--------------------------------------------------------------------------------
★ 종합 판정 (먼저 읽을 것)
--------------------------------------------------------------------------------
 제어(FSM·카운터·valid 윈도우·skew·de-skew·타일 전환)는 전부 설계식 그대로
 동작한다. 그러나 누산값이 기대치의 정확히 7/8 이다:

    관측: 0.21875 / 0.328125 / 0.4375 / 0.546875
    기대: 0.25    / 0.375    / 0.5    / 0.625        (비율 = 7/8)

 원인: A(입력)·B(가중치) 메모리 BMG 모두 Primitives Output Register가 ON
       → 읽기 지연이 설계 전제(1클럭)가 아닌 2클럭.

   [B 지연 2의 효과] LOAD의 첫 shift-in 에지에 아직 데이터가 도착하지 않아
       "0"이 먼저 들어가고, 마지막 가중치 워드는 shift 창이 닫힌 뒤 도착해
       버려진다. → SA 맨 아래 행(row7) 가중치가 전부 0
       → 8행 중 7행만 계산에 기여 → 모든 값이 7/8.

   [A 지연 2의 효과] 입력 스트림 전체가 1클럭 늦게 흘러
       → 뱅크 쓰기 주소가 한 칸 밀림 (위치 p의 값이 주소 p+1에 저장,
         주소 0에는 스트림 시작 전의 0이 저장), 마지막 위치 195는
         valid 창이 닫힌 뒤라 아예 기록되지 못함.

 증거 (캡처 안에서 직접 확인 가능):
   ① 캡처1: B doutb가 읽기 시작(35ns) 후 2클럭 뒤(55ns)에야 f8000800…으로
      바뀜 — 지연 2클럭.
   ② 캡처2~9 공통: w_wire[8](맨 아래 행의 w_reg 관찰점)이 끝까지 0.0
      — 정상이라면 ±0.03125 이어야 함.
   ③ 모든 누산값이 정확히 7/8 배율 (한 행 결손의 산술적 서명).
   ④ 캡처4: 뱅크0의 첫 값이 설계식(cnt 14)보다 1클럭 늦은 cnt 15에 등장
      — A 지연 2의 서명.

 조치: 두 메모리 모두 재커스터마이즈 → Port B Options →
       Primitives Output Register 체크 해제 → Generate → 재시뮬.
       (이 옵션은 수백 MHz급 Fmax를 위한 것 — 100MHz에서는 불필요하며,
        설계 전체가 지연 1클럭(MEM_LAT=1) 전제로 정렬되어 있음.)
       수정 후 재캡처하면 아래 각 캡처의 "수정 후 기대값"대로 나와야 한다.

--------------------------------------------------------------------------------
1_Load_mode가 켜질때.png  (커서 35ns)
--------------------------------------------------------------------------------
 상황: start 펄스 직후, FSM이 IDLE→LOAD로 진입하는 순간.
  - n_state가 한 클럭 먼저 1(LOAD)이 되고, load_mode는 35ns 에지에서 상승.
    → "n_state 기준 레지스터 출력" 설계 그대로 (글리치 없는 1클럭 정렬).
  - load_cnt가 0→1→2→3 증가 시작, B 주소(addrb[11:0])가 000→001→002
    → w_rd_addr = (filter_tile×8+ch_tile)×8+load_cnt = 첫 타일이므로 0부터.
  - B doutb: 0이다가 55ns에 f8000800f8000800… 등장.
    f800 = -2048 = -0.03125(홀수 필터), 0800 = +2048 = +0.03125(짝수 필터)
    → 디버그 가중치가 맞게 읽힘. 단, 등장 시점이 2클럭 뒤 = 지연 2 (문제!).
  - x_wire 전 행 0, calc_cyc_cnt=0, 모든 BANK acc=0.0 — 아직 계산 전.

--------------------------------------------------------------------------------
2_Load_mode가 꺼질때.png  (커서 115ns)
--------------------------------------------------------------------------------
 상황: LOAD 8클럭 종료 → CALC 진입 직전.
  - load_cnt가 8에 도달, n_state=2(CALC), load_mode 하강, c_state 1→2.
  - w_wire 행들이 시간차를 두고 ±0.03125로 채워지는 계단이 보임
    = shift-in 파면이 아래로 내려간 흔적.
  - ★ w_wire[8][*] = 0.0 유지 — 맨 아래 행 가중치가 0 (원인 증거②).
    수정 후 기대: 8클럭 로드가 끝나면 w_wire[1]~[8] 전부 ±0.03125.
  - A 주소가 000부터 움직이기 시작(CALC 읽기), calc_cyc_cnt 0→1→2.

--------------------------------------------------------------------------------
3_계산 카운트 시작.png  (커서 125ns)
--------------------------------------------------------------------------------
 상황: CALC 첫 클럭들. 입력 스트리밍 개시.
  - calc_cyc_cnt = 0,1,2,3…, A 주소 = 위치 번호 그대로 (x_rd_addr 공식).
  - A doutb: 1000 1000 …(=1.0 여덟 개) → 1800…(1.5) → 2000…(2.0) —
    위치 p%4 = 0,1,2의 디버그 입력이 순서대로 온다. 단, 도착 시점이
    주소 제시 후 2클럭 (출력 레지스터 ON) — 설계 전제(1클럭)보다 늦음.
  - x_wire[0] 행에 1.0이 먼저 나타나고 아랫행들은 아직 0
    → Skew_Regs가 행마다 1클럭씩 늦게 흘리는 계단의 시작.
  - 모든 BANK 아직 0 — 첫 psum은 cnt 13 이후에나 나온다 (OFFSET).

--------------------------------------------------------------------------------
4_뱅크0_valid켜짐.png  (커서 255ns)
--------------------------------------------------------------------------------
 상황: 첫 완성 psum이 배열 바닥에 도착 — BANK[0] 쓰기 시작.
  - calc_cyc_cnt 13→14 되는 에지에서 BANK[0].valid_d 상승.
    valid[0] = (cnt≥13) 이고 valid_d는 그 1클럭 지연판 → 설계식 그대로.
  - 단, acc_new의 첫 유효값(0.21875)은 cnt 15에 등장 — 설계식(cnt 14)보다
    1클럭 늦음 = A 메모리 지연 2클럭의 서명 (종합 판정 ④).
  - x_wire 계단이 완성된 모습: 행0 "1.0,1.5,2.0,2.5…" 대비 행7은
    7클럭 늦게 시작 — skew 대각 파면이 육안으로 보임.
  - BANK[0].acc_new 순서: 0.21875 → 0.328125 → 0.4375 → 0.546875
    · 비율 1 : 1.5 : 2 : 2.5 = 입력 패턴 그대로 (위치 매핑 정확)
    · 절대값은 기대(0.25/0.375/0.5/0.625)의 7/8 (문제의 서명)
    · 첫 채널 타일이므로 first_ch_tile bypass로 "그대로 저장" 경로.
  - 수정 후 기대값: 0.25 → 0.375 → 0.5 → 0.625 반복.

--------------------------------------------------------------------------------
5_뱅크1_valid켜짐.png  (커서 265ns)
--------------------------------------------------------------------------------
 상황: BANK[0]보다 정확히 1클럭 뒤에 BANK[1] 시작.
  - 열 j의 출력은 j클럭 늦게 나온다(출력 skew) → 뱅크 valid_d가
    1클럭 간격 계단으로 서는 것이 de-skew 동작의 증거.
  - BANK[1].acc_new = -0.21875 → -0.328125 → … : 필터1은 가중치가
    -0.03125이므로 BANK[0]의 정확한 부호 반전. 열↔필터 매핑 확인.
  - 수정 후 기대값: -0.25 → -0.375 → -0.5 → -0.625 반복.

--------------------------------------------------------------------------------
6_뱅크2_valid켜짐.png  (커서 275ns)
--------------------------------------------------------------------------------
 상황: 다시 1클럭 뒤 BANK[2] 시작 (계단 계속).
  - BANK[2] = 필터2(짝수) → 양수 +0.21875… BANK[0]과 같은 수열이
    2클럭 밀려서 나타남. 세 뱅크의 시간차·부호가 모두 이론과 일치.

--------------------------------------------------------------------------------
7_뱅크0_valid꺼짐.png  (커서 2,215ns)
--------------------------------------------------------------------------------
 상황: 첫 타일의 마지막 위치들 — DRAIN 구간에서 뱅크0 창이 닫힘.
  - c_state=3(DRAIN), load_mode=0. calc_cyc_cnt 210에서 BANK[0].valid_d 하강
    → 유효 구간 길이 = 정확히 196클럭(위치 196개). 설계 윈도우
      [13, 13+196) + 1클럭(valid_d) 그대로.
  - A 주소는 0d0~0d4(208~212)까지 계속 증가하지만 x_rd_en이 꺼져
    doutb는 마지막 값(2000…)을 유지 — 주소만 돌고 읽기는 안 함(정상).
  - 뱅크 값은 마지막 갱신값(0.4375 등)을 유지한 채 멈춤.

--------------------------------------------------------------------------------
8_뱅크1_valid꺼짐.png  (커서 2,225ns)
--------------------------------------------------------------------------------
 상황: 1클럭 뒤 BANK[1] 창 닫힘 (cnt 211). 마지막 값 -0.4375 유지.
  - 켜질 때와 같은 1클럭 계단으로 꺼짐 — 켜짐/꺼짐 모두 j클럭 오프셋.

--------------------------------------------------------------------------------
9_뱅크2_valid꺼짐.png  (커서 2,235ns)
--------------------------------------------------------------------------------
 상황: 또 1클럭 뒤 BANK[2] 창 닫힘 (cnt 212).
  - 이로써 "열 j 윈도우 = [13+j, 13+j+196)" 공식이 켜짐 3장 + 꺼짐 3장으로
    완전히 검증됨.

--------------------------------------------------------------------------------
10_두번째 Load_mode 켜짐.png  (커서 2,305ns)
--------------------------------------------------------------------------------
 상황: 첫 타일 완전 종료 → 두 번째 채널 타일 진입.
  - calc_cyc_cnt가 218(CYC_END)에 도달 → 219 한 클럭 → 0으로 리셋,
    c_state 3(DRAIN)→1(LOAD), load_mode 재상승, ch_tile 0→1.
  - B 주소가 008,009,00a… = (0×8+1)×8+load_cnt — 두 번째 타일 가중치
    (채널 8~15) 주소식 그대로.
  - A 주소가 과도값 19f(=1×196+219)를 잠깐 보였다가 0c4(=196, 타일1의
    위치0)로 정착 — ch_tile×196+cnt 공식의 자연스러운 전환.
  - 뱅크 acc_new가 0.0/X로 보이는 것은 valid=0 구간의 무의미한 주소를
    읽은 값이라 무해 (쓰기는 valid_d로 게이트되어 있음).
  - 이 타일부터는 first_ch_tile=0 → RMW 누산 경로: 다음 valid 구간에서
    acc가 이전 값 위에 쌓여 (수정 후 기준) 0.25→0.5→…처럼 커진다.
    ch_tile 7이 끝나면 last_ch_tile=1과 함께 완성값 ±2.0/3.0/4.0/5.0이
    out_valid로 배출된다.

--------------------------------------------------------------------------------

     - 캡처2: LOAD 종료 시 w_wire[1]~[8] 전부 ±0.03125 (0.0 행 없음)
     - 캡처4: 뱅크0 첫 값이 cnt 14에 등장 (1클럭 밀림 해소)

  3. (보고서용 추가 캡처 권장) ch_tile=7 구간: last_ch_tile=1과 함께
