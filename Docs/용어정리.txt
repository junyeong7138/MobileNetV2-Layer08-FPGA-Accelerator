================================================================================
 Layer08 Pointwise Conv — 용어 정리
 (PW1 확장 단계 기준: 입력 64ch × 14×14 → 출력 384ch × 14×14)
================================================================================

--------------------------------------------------------------------------------
1. 데이터 쪽 용어
--------------------------------------------------------------------------------
■ 위치 (= 픽셀, position, p)
   14×14 평면 위의 한 점. 총 14×14 = 196개. 코드/파형의 p, out_pos가 이것.
   ※ "196개"는 채널 개수가 아니라 "채널 한 장 안의 픽셀 개수"다!

■ 채널 (channel)
   14×14 픽셀 196개가 모인 "한 장의 평면(지도)".
   - 입력 채널: 64장   (Layer07이 만들어 준 것)
   - 출력 채널: 384장  (PW1이 만들어야 하는 것. 필터 1개가 출력 채널 1장을 만듦)
   입력 전체 = 64장 × 196픽셀 = 12,544개 숫자 (Q3.12)

■ 필터 (filter)
   출력 채널 한 장을 만드는 가중치 묶음. PW(1×1) conv라서
   필터 1개 = 1×1×64 = 숫자 64개 (입력 채널마다 1개씩).
   필터가 384개 → 가중치 전체 = 384 × 64 = 24,576개 (2^-16 스케일).

■ 출력값 하나는 어떻게 만들어지나
   출력[필터 f][위치 p] = Σ(64개 채널 c에 대해) 입력[c][p] × 가중치[f][c]
   = "같은 위치 p의 입력 64개"와 "필터 f의 가중치 64개"의 내적.
   이걸 f 384개 × p 196개 = 75,264번 하는 것이 PW1 전부다.

--------------------------------------------------------------------------------
2. 하드웨어 쪽 용어
--------------------------------------------------------------------------------
■ PE (ProcessingElement) — 8×8 = 64개
   곱셈 1개 + 덧셈 1개 + 전달. 각 PE는 가중치 1개(w_reg)를 물고 있다.
   - 행(row, 세로 방향 8개) = "입력 채널" 축  → 행 i는 채널 (ch_tile×8 + i) 담당
   - 열(column, 가로 방향 8개) = "필터" 축    → 열 j는 필터 (filter_tile×8 + j) 담당
   즉 PE(i,j)의 w_reg = 필터(…+j)의, 채널(…+i)에 대한 가중치 1개.

■ SystolicArray (SA)
   PE 64개의 격자. CALC 동안:
   - 입력 x는 왼쪽→오른쪽으로 흐른다 (같은 입력을 8개 필터가 재사용)
   - 부분합 psum은 위→아래로 흐른다 (내려가며 8개 채널 몫이 쌓임)
   열 j의 맨 아래에서 매 클럭 "위치 1개의 8채널 부분 내적"이 완성돼 나온다.

■ 뱅크 (BANK[0]~[7], Accum_Buffer 내부) — 열마다 1개, 총 8개 (PE 아님!)
   깊이 196(=위치 수) × 32b 메모리. "필터 한 개의 14×14 출력 지도"를
   8번에 나눠 그리는 스케치북. 주소 = 위치 p.
   bypass(첫 겹) → RMW 누산(2~7겹) → 마지막 겹에서 완성값 배출.

■ skew / de-skew
   skew: 입력 행 i를 i클럭 늦게 넣는 계단 (Skew_Regs) — 배열 타이밍 맞추기용.
   de-skew: 열 j의 출력이 j클럭 늦게 나오는 계단을 뱅크 쓰기 주소 시작을
   j클럭 늦춰서 흡수하는 것.

--------------------------------------------------------------------------------
3. 실행 단위 용어 (여기가 제일 헷갈리는 부분)
--------------------------------------------------------------------------------
■ 타일 (tile)
   가중치 행렬(64행×384열)을 배열 크기(8×8)로 자른 "조각" 하나.
   = (채널 8개) × (필터 8개) 가중치 64개 묶음.
   세로로 8묶음(ch_tile 0~7) × 가로로 48묶음(filter_tile 0~47) = 총 384조각.

■ 창 (valid window) = 타일 1개의 처리
   LOAD(8클럭, 조각의 가중치 64개 로드)
   → CALC(196클럭, 위치 0~195 스트리밍)
   → DRAIN(19클럭, 파이프 배출)
   파형에서 뱅크 0~7 valid가 계단으로 켜졌다 꺼지는 것 하나가 창 하나다.
   창 하나 동안 계산되는 것: 필터 8개 × 위치 196개 × "채널 8개 몫"(부분합).
   → 창 하나가 끝나도 완성된 출력 채널은 0개! (1/8 겹을 칠했을 뿐)

■ 루프 순서 (우리 FSM, 매우 중요)
   for (filter_tile = 0 → 47)        ← 바깥 루프: 필터 8개 묶음
       for (ch_tile = 0 → 7)         ← 안쪽 루프: 채널 8개 묶음
           창 1개 (LOAD+CALC+DRAIN)
   ▶ "채널을 먼저 다 돌고, 그 다음 필터 묶음으로 넘어간다."
   ▶ 8창(ch_tile 0~7)이 끝나는 순간 = 필터 0~7의 출력 채널 8장이
     "동시에" 완성·배출 (last_ch_tile, out_valid). 이게 48번 반복.
   ※ 반대로 필터를 먼저 다 도는 순서도 이론상 가능하지만, 그러면
     384필터 전부의 미완성 부분합을 동시에 보관해야 해서 누산 버퍼가
     48배(8뱅크 → 384뱅크분) 필요해진다. 채널을 안쪽에 둔 이유다.

■ 부분합 / 완성값
   부분합: 64항 내적 중 8항씩만 더한 중간값 (뱅크에 저장; 디버그셋 0.25 등)
   완성값: 8겹이 다 쌓인 최종 내적 (out_data로 배출; 디버그셋 ±2.0~5.0)

--------------------------------------------------------------------------------
4. 카운터/신호 (파형에서 보는 것들)
--------------------------------------------------------------------------------
   load_cnt        : LOAD 진행 (0~7) — 가중치 8행 shift-in
   calc_cyc_cnt    : CALC 시작부터 센 클럭. CALC 중엔 "지금 몇 번째 위치를
                     흘리는가"(=입력 읽기 주소), DRAIN까지 이어져 valid 기준.
   ch_tile_cnt     : 지금 처리 중인 채널 묶음 (0~7). 안쪽 루프.
   filter_tile_cnt : 지금 처리 중인 필터 묶음 (0~47). 바깥 루프.
   valid[j]        : 열 j의 psum이 진짜 데이터인 구간 (13+j ~ 13+j+196)
   first_ch_tile   : ch_tile==0 → 뱅크에 "그대로 저장" (bypass)
   last_ch_tile    : ch_tile==7 → 완성값 배출 구간
   out_valid/out_data/out_pos : 완성값 스트림 (8창마다 한 번, 총 48번)
   done            : 384창이 모두 끝난 뒤 1클럭 펄스

--------------------------------------------------------------------------------
5. 질문 4개 첨삭 (O/X)
--------------------------------------------------------------------------------
Q1. "입력의 14×14는 196개잖아. 이게 하나의 채널? 그럼 196개의 채널이
    384개 있다는 거지?"
  → 반은 O, 반은 X.
    O: 14×14 = 196개의 "픽셀"이 모인 것이 채널 한 장이다.
    X: "196개의 채널"이 아니다. 196은 채널 개수가 아니라 채널 한 장 안의
       픽셀 개수. 입력 채널은 64장, 출력 채널이 384장이다.
       (입력 = 196픽셀짜리 지도 64장 / 출력 = 196픽셀짜리 지도 384장)

Q2. "가중치는 1×1짜리로 그 뒤쪽으로 64개 채널, 밑으로 384개 필터?"
  → O. 정확하다. 필터 1개 = 1×1×64(채널당 1개씩 64개 숫자),
    그런 필터가 384개. 총 24,576개.

Q3. "PE 가로 8개는 위에서 가중치가 들어오는데, 8줄 각각 서로 다른
    필터에서 들어오는 거야?"
  → O. 세로 '열' 8개가 각각 다른 필터 담당이다.
    열 j에 위→아래로 들어가는 8개 값 = "필터 j의 가중치 64개 중,
    지금 채널 묶음(8개)에 해당하는 8개"다.

Q4. "196 계산이 끝나면 필터 9,10,… 총 384필터까지 돌고, 그러면 64채널 중
    제일 앞 채널만 끝난 거잖아?"
  → X. 루프 순서가 반대다!
    우리 설계는 필터 0~7에 대해 "채널 묶음 8개를 먼저 전부" 돈다:
       창1: 필터0~7 × 채널0~7   (부분합 1겹)
       창2: 필터0~7 × 채널8~15  (2겹째 누산)
       ⋮
       창8: 필터0~7 × 채널56~63 (8겹째 = 완성! 필터 0~7 출력 배출)
       창9: 필터8~15 × 채널0~7  (다음 필터 묶음 시작)
       ⋮
    → 8창마다 필터 8개의 출력이 "완전히" 끝난다.
    질문의 순서(필터를 먼저 전부)는 다른 타일링 순서이며, 그렇게 하면
    384필터 전체의 부분합을 동시에 들고 있어야 해서 누산 버퍼가 48배
    커진다. 그래서 채널을 안쪽 루프로 정했다.

--------------------------------------------------------------------------------
6. 숫자 한눈 요약
--------------------------------------------------------------------------------
   위치(픽셀)          : 196개 (14×14)
   입력 채널           : 64장   → 입력 숫자 12,544개
   필터 = 출력 채널    : 384개  → 가중치 24,576개, 출력 숫자 75,264개
   PE                  : 8행(채널축) × 8열(필터축) = 64개
   뱅크                : 8개 (열/필터마다 1개, 깊이 196)
   타일(=창)           : 8(ch) × 48(filter) = 384개, 창당 ≈227클럭
   완성값 배출         : 8창마다 1회 × 48회 (한 번에 채널 8장씩)
   전체                : 87,169클럭 ≈ 0.87ms @100MHz, 끝나면 done 1클럭
